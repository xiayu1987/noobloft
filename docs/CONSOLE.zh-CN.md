# 管理控制台

## 界面语言

控制台左下角可选择「简体中文 / English」。首次按浏览器语言选择，之后保存在浏览器的 `noobloft.language` 偏好中；退出登录不会清除语言偏好。切换同时更新表单组件、日期格式和后端资源说明，不会改变输入中的模型名、PeerID、路径或签名文档。

CLI 使用全局参数：`noobloftd --lang en manage help`、`noobloftd --lang zh-CN publisher service -h`。Windows 命令加 `.exe`。优先级为 `--lang`、`NOOBLOFT_LANG`、`LC_ALL`、`LC_MESSAGES`、`LANG`，无匹配时使用中文。Windows 托盘启动时同样读取该参数或环境变量，已运行的托盘不会随浏览器切换语言。托盘窗口识别标题保持固定，避免停止脚本和单实例唤醒受语言影响。

开发约定：中文与英文分别位于 `locales/zh-CN.json` 和 `en.json`，前端、CLI、托盘与管理接口共用同一词库。调用必须使用稳定语义 key（例如 `nav.overview`、`issuer.revoke.confirm`）；更改措辞只改词库，不以中文原文作为 key。两种语言必须具有相同 key 和格式占位符。运行 `go test ./internal/localization` 检查一致性；前端类型检查也会检查 key。HTTP 管理请求通过 `Accept-Language` 指定显示语言；JSON 字段、资源 kind、状态码、签名内容保持不变。系统/第三方返回的技术错误保留原始内容。项目文档提供中英两版：`X.md` 为英文，`X.zh-CN.md` 为中文，顶部互相链接，修改时两版需同步更新。

## 启动与登录

使用已有节点目录启动 `noobloftd run -dir <节点目录>`。网关启用时，启动输出会给出管理台地址，默认 http://127.0.0.1:8760/ 。第一次启动自动在节点目录生成独立的 `admin.token`；从本机读取该文件并粘贴到登录页。它拥有节点管理权限，不要作为模型调用 token 分发。

前端静态资源嵌入 Go 可执行文件，部署后无需 Node.js 或 Nginx。网关配置 token 及后端 API key 不通过状态接口返回。

### 一键启动与后台运行

关闭脚本：Windows 执行 `.\scripts\stop.ps1`，自定义节点目录用 `--dir D:\node1`；
Linux 执行 `sudo sh scripts/stop.sh`，自定义目录加 `--dir /srv/noobloft`，默认调用者家目录下 `.noobloft`。停止匹配目录的服务及命令行节点，无需 Force；命令行节点先 SIGTERM，30 秒未退出再 SIGKILL。需要 Python 3.9+、Linux 5.3+（pidfd 支持）；其他目录不受影响。
两者都支持重复执行，保留节点数据。Windows 请求托盘正常退出、不弹确认框，默认最多等待 30 秒，
可用 `--timeout` 调整。脚本默认也停止手工 `run` 的节点，无需额外开关：
仅终止本项目 `bin\noobloftd.exe` 中显式使用绝对路径 `-dir` 且目录匹配的命令行节点。需要正常退出时可先在原窗口按 Ctrl+C。
强制停止会中断请求，无法保证内存数据落盘；其他目录和无法可靠识别的进程不会被终止。
旧版托盘需先从菜单退出，再运行启动脚本升级。Linux 保留开机自启，停止后不会被失败重启策略拉起；
取消开机自启请另执行 `sudo systemctl disable noobloft`。

`scripts/start.ps1`（Windows）和 `scripts/start.sh`（Linux）已完成「构建 → 初始化 → 后台拉起」，并已包含初始化，不需要单独的初始化脚本。

发布者授权模式首次启动：Windows 使用 `.\scripts\start.ps1 --mode shared`；Linux 使用 `sh scripts/start.sh --mode shared`。无需先执行 `init -mode shared`。模式参数只对没有 `config.json` 的目录生效；已有目录继续使用原配置，不会因为再次传入 shared 就迁移模式。不传模式时默认 private。两个平台的脚本参数名一致（`--mode`、`--dir`、`--help`，单横线写法等价），未知参数会直接报错而不是被当成节点目录。参数说明统一使用 `--help`。

```powershell
.\scripts\start.ps1                                                # 默认 %USERPROFILE%\.noobloft
.\scripts\start.ps1 --dir D:\node1 -- -profile wan -join D:\swarm.key  # `--` 之后的参数透传给首次 init
```

```sh
scripts/start.sh                                                   # 默认 ~/.noobloft
scripts/start.sh --dir /srv/noobloft --user llm
scripts/start.sh --dir /srv/noobloft -- -profile wan -join /tmp/swarm.key
```

**幂等**：可重复执行，不会覆盖已有数据。二进制缺失或比源码旧才构建；节点目录已有 `config.json` 时跳过 `init`；Linux 侧安装到 `/usr/local/lib/noobloft/` 时内容相同不覆盖，systemd unit 内容不变不重写，服务在运行且二进制与 unit 都没变时不重启。

**Windows 托盘**：节点在后台运行，不占控制台窗口。单击右下角托盘图标唤出状态窗口；关闭窗口或最小化只隐藏到托盘，节点继续运行；只有托盘图标右键「退出」或状态窗口里「停止并退出」才真正停止节点。再次运行 `start.ps1` 不会起第二个实例，只把已有窗口调到前台。若目标端口已被其他进程占用，脚本会报出占用者的 PID 与进程名并以退出码 1 结束，不会把别人的 `/healthz` 误判为本次启动已就绪；此时改 `gateway.bindAddr` 或先停掉占用者。

Windows 构建会生成 `bin\noobloftd.exe`（命令行版）和 `bin\noobloftd-tray.exe`（`-H=windowsgui` 托盘版）。
启动脚本自动使用托盘版，从进程创建时就没有控制台窗口；原来的 `publisher`、`init` 等命令行输出不受影响。
首次运行 `scripts\start.ps1` 初始化，之后可双击托盘版启动默认节点，或加 `-dir <已有节点目录>`。
旧 `noobloftd tray` 入口仍保留，但无控制台启动应使用托盘版。升级前请自行退出旧实例，脚本不会强制停止节点。

**Linux 服务**：注册 systemd 服务 `noobloft` 并设开机自启，之后用 systemctl 管理。

```sh
systemctl status noobloft      # 状态与最近日志
systemctl restart noobloft     # 改配置或换二进制后重启
systemctl stop noobloft        # 停止
journalctl -u noobloft -f      # 跟踪日志
```

`start.sh` 注册系统服务需要 root，非 root 调用时经 `sudo` 重新执行自身；节点进程以调用者身份运行（`sudo` 时取 `SUDO_USER`，或用 `--user` 指定），节点数据不会变成 root 所有。`--` 之后的参数只在首次初始化时透传给 `init`。`noobloftd tray` 是 Windows 专用子命令，在 Linux 上会被拒绝并提示改用 `systemctl`。

两种方式下 `admin.token`、`node.log` 的位置都不变，仍在节点目录里。

### 登录会话（免登录）

- 登录时用 `admin.token` 换取会话 cookie `noobloft_session`：`HttpOnly`、`SameSite=Strict`、`Path=/manage`，有效期 7 天。页面脚本读不到它，也不写 localStorage、sessionStorage 或 URL。
- cookie 内容是「过期时间 + 以 admin.token 为密钥的 HMAC」，不包含 admin.token 本身，服务端不保存会话，所以**刷新页面、重启节点都不用重新登录**。
- 点「退出」会清掉本浏览器的 cookie。服务端无法单独作废某一个会话：如果 cookie 被复制走，到期前仍然可用。怀疑泄漏时删除节点目录里的 `admin.token` 并重启节点，会生成新凭证，所有已登录浏览器立即失效。
- 防跨站请求伪造：凭 cookie 发起的写操作（POST/PUT/DELETE）必须带与 Host 一致的 `Origin`，否则返回 403；`Authorization: Bearer <admin.token>` 方式仍然可用，供脚本调用。

网关关闭时不提供控制台。保持默认回环监听；远程管理可以通过 SSH 本地端口转发。直接暴露 HTTP 网关不提供 TLS 保护。

## 页面

- **概览**：PeerID、运行模式、运行网关、保存订阅数量、待重启状态。
- **微网络订阅**：导入签名服务描述，明确核对可信发布者 ID；再导入绑定当前 PeerID 的消费凭证。支持更新文档、移除订阅、查看有效期与模型许可。
- **我的发布服务**：顶部为授权状态总览，列出服务委托、吊销快照、模型服务与可服务模型；下方按严重度列出问题项，每条给出建议动作。安装授权本节点的服务委托及签名吊销快照；查看服务身份、模型、授权节点和吊销项目。通过“导出服务描述”下载完整签名的 `service.noobloft`，支持选择运行中或已保存配置。安装后还需在配置里启用模型服务。
- **模型与调试**：查询运行时模型，支持手填 `发布者ID::模型名`，发送单轮流式请求与取消；生成上限为 256 token。调用消耗真实授权额度。输出以纯文本渲染。
- **节点与连接**：显示当前连接节点的模型、发布者归属、连接路径、查询错误和信誉观测。
- **节点配置**：右侧抽屉编辑模型后端、服务开关、模型许可、网络地址、发现、中继白名单、信誉抽检和网关参数。后端 API key 留空保留同名后端的已有值；清空已有密钥目前通过 CLI 配置处理。

### 直接签发与吊销（Windows / Linux 通用）

在“我的发布服务 → 发布者签发管理”点击“启用本机在线签发”。这会创建独立发布者身份，与节点 PeerID 分开；不会替换已有离线发布者。私钥仅由后端读取，浏览器不上传、不保存、不下载私钥。持有本机管理权限就能签发，因此应保持回环监听，通过 SSH 转发远程管理。

1. 点击“签发服务委托”，模型与服务节点预填当前配置；签发后在记录中“安装到本机”。在节点配置启用模型服务并重启，委托开始生效。
2. 点击“签发消费凭证”，填写消费者 PeerID、模型和限额。下载记录中的凭证，交给消费者导入；服务描述也需要先交给消费者订阅。
3. 收回一张凭证时，在记录中点击“吊销”。收回某个消费者的所有权限时，使用“吊销消费者”。消费者身份吊销不可通过重新签发恢复；单张凭证吊销可另签新凭证。
4. 本机已安装的同发布者名单自动应用，新请求无需重启即可检查新版名单。界面分别显示本机运行状态与其他节点未确认状态。已有请求不会被主动中断。

**吊销快照是什么？** 假设小王拿到编号 A 的通行证。收回权限时，无法拿回他电脑上的证件，于是把 A 写入“作废名单”。门卫收到名单后，看到 A 就拒绝。快照就是这份完整名单的签名文件；序号表明新旧，签名防止篡改，有效期防止节点一直拿旧名单放行。无人被吊销时名单为空，但仍要有有效签名。

平台自动保留旧吊销项、递增版本。网关运行期间每分钟检查一次，名单有效期 7 天、剩余不足 48 小时自动续签；服务委托和消费凭证不会自动延期授权。网关关闭期间无法续期，重启后恢复维护。名单丢失、损坏、过期仍拒绝请求，不绕过校验；维护错误显示在签发管理中。

**多节点边界：当前没有远端自动分发通道。** 点击“导出作废名单”，在每个服务节点使用原有“更新签名吊销快照”导入，确认当地版本。远端仍可能在旧名单到期前接受旧凭证，因此不能将本机成功视为全网立即吊销；续签后的名单也需分发。

备份整个 `<节点目录>/publisher-authority`，其中 `identity.key` 是独立签名私钥、`issued/` 是签发记录、`revocations.json` 是完整作废名单。Linux 创建目录权限 0700、文件 0600；Windows 应用目录继承 Windows ACL，请将节点目录限制为运行账户。不要删除名单或仅恢复旧名单，否则可能丢失吊销历史。私钥丢失不会自动生成新身份。

已有离线发布者继续使用 [发布者微网络](PUBLISHERS.zh-CN.md) 的 CLI 与签名文件导入流程。在线签发建立的是新身份，不会自动接管旧根密钥或导入旧签发历史；页面记录仅覆盖本签发端。签发接口 `/manage/issuer` 复用管理鉴权、同源校验和写锁，写操作要求配置版本 `If-Match`。

### 恢复初始配置与创建全新节点

在「资源管理与使用说明 → 恢复与维护」点击「恢复初始配置」。右侧抽屉预览目录、PeerID 与影响范围，输入 `RESET CONFIG` 后备份、恢复并自动重启。恢复复用 init 的默认配置：恢复本地 Ollama 后端，清除订阅和已安装服务委托，发布与中继服务关闭，网络发现、监听及策略恢复默认值。

保留节点身份、网络模式、私网密钥、当前管理入口和凭证、发布者身份、签发历史、累计吊销名单及日志。恢复不是吊销，已发出的授权不会因此失效。P2P 地址可能变化，外部固定连接需重新核对。

抽屉也可选择已有配置备份，恢复该备份的业务配置（可能重新启用发布、中继或订阅），仍保留当前网络模式、管理入口及凭证；执行前再备份当前配置。不会恢复旧吊销名单。旧服务凭证可能已到期或已吊销，配置恢复后需在授权页核对准入状态。

Windows/Linux CLI 共用同一接口（Windows 程序名为 `noobloftd.exe`）：

```text
noobloftd manage reset -dir <节点目录>
noobloftd manage reset -dir <节点目录> -revision <预览返回的revision> -confirm "RESET CONFIG"
noobloftd manage reset -dir <节点目录> -revision <预览返回的revision> -confirm "RESET CONFIG" -backup config.before-reset-<时间戳>.json
noobloftd manage resources -dir <节点目录>
```

不带确认参数只预览；执行时 revision 必填，预览后配置变化会拒绝执行。backup 选填，必须是本节点备份文件名，不能传任意路径。CLI 等待结果；超时只表示结果未知，可再次查询 resources。

`config.json` 是保存配置，运行副本决定当前行为；`recovery.json` 记录最近操作 ID、状态及备份名。`pending` 表示等待启动验证，`completed` 表示网关启动且加载配置与目标一致，`rolled_back` 表示失败后旧配置已写回，`failed` 表示恢复写入或目标核验失败。完成不代表外部模型、授权或网络连通性检查通过。启动失败自动回退并尝试启动旧配置；若旧配置也无法启动，查看日志并本机修复。浏览器断线不会触发回退。

备份位于节点目录 `config.before-reset-*.json`，含敏感配置，应与节点目录同等保护。操作失败保留备份；不删除身份、名单或历史文件。

要创建全新身份：先停止旧节点，再用 start 指定**全新目录**（Windows `-Dir`，Linux `--dir`），原目录保留归档。新节点默认管理端口与旧节点相同，不可直接同时启动；原发布者仍需维护名单直到旧授权到期。这是独立操作，不通过网页删除当前运行目录。

### 授权状态总览

状态由服务端按最高严重度计算，浏览器不做二次判断：**授权有效**（绿）表示委托、快照与模型服务齐备；**需要留意**（黄）表示仍可接单，但有材料将在 72 小时内到期；**不会接单**（红）表示存在阻断项，远程调用会被拒绝。

问题项分三级：`blocked` 直接拒绝请求，包括未安装服务委托、服务描述校验失败或已过期、委托不含本节点、吊销快照缺失/不可读/校验失败/已过期、本节点或当前服务被吊销、模型服务未启用、公告模型与委托模型无交集；`warning` 影响可用范围，包括 72 小时内到期、公告模型不在委托范围内、已启用但没有可服务模型；`info` 为待重启提示。判定与准入逐条对齐：缺失或无效文档一律 fail-closed，吊销快照每次请求重新读取。

状态接口为只读 `GET /manage/authorization`，不修改配置、不读取任何私钥路径。点击“按建议处理”会打开对应的安装抽屉或签发命令助手；`provider_disabled`、`advertised_not_delegated` 一类需要改配置的项目跳到“节点配置”。

### 签发命令助手

“我的发布服务 → 签发命令助手”按服务描述、消费凭证、吊销快照三类生成可直接粘贴的执行命令，包含 `-root`、`-file`、`-peers`、`-models`、`-addresses`、`-relays`、`-subject`、`-revoked`、`-previous`、`-ttl`、`-max-tokens`、`-concurrency`、`-rpm`。根身份目录只作为文本写入命令，服务端不读取、不校验、不保存；浏览器内不创建根身份、不签发任何文档。复制使用剪贴板 API，在非安全上下文自动降级为选区复制，失败时提示手动选取而不关闭抽屉。

每个字段的标签都标明“必录 / 选填”和默认值；必录项未填时“复制命令”不可用。

| 字段 | 适用类别 | 必录 | 默认值 | 说明 |
|---|---|---|---|---|
| 根身份目录 `-root` | 全部 | 必录 | 无 | 离线签发机器上的发布者根身份目录 |
| 输出文件 `-file` | 全部 | 必录 | CLI 无默认值；助手预填为 **根身份目录下** 的 `service.noobloft` / `consumer-access.json` / `revocations-1.json`，随 `-root` 与签发类别联动，手工改过后不再覆盖 | CLI 按命令执行时的当前目录解析相对路径，因此默认给完整路径，签发结果落在根身份目录里；签发命令不会覆盖已有文件 |
| 授权服务节点 `-peers` | 服务描述 | 必录 | 本节点 PeerID | 多个用逗号分隔 |
| 授权模型 `-models` | 服务描述、消费凭证 | 必录 | 消费凭证预填服务描述里的模型 | 显式模型名，不接受 `*` 或 `发布者ID::模型名` |
| 连接地址 `-addresses` | 服务描述 | 选填 | 本节点 `network.announceAddrs` + `/p2p/<本节点PeerID>` | 见下文 |
| 中继地址 `-relays` | 服务描述 | 选填 | 无 | 必须以 `/p2p/<中继PeerID>` 结尾 |
| 消费者 PeerID `-subject` | 消费凭证 | 必录 | 无 | 凭证只对该 PeerID 生效 |
| 单次最大生成 token `-max-tokens` | 消费凭证 | 必录 | 1024 | 正整数 |
| 并发上限 `-concurrency` | 消费凭证 | 必录 | 1 | 每个服务节点上的并发请求上限 |
| 每分钟请求上限 `-rpm` | 消费凭证 | 必录 | 30 | 每个服务节点上的每分钟请求上限 |
| 吊销目标 `-revoked` | 吊销快照 | 选填 | 空 | 凭证 ID、消费者 PeerID 或服务 ID；首次签发可为空快照 |
| 上一份快照 `-previous` | 吊销快照 | 选填 | 无 | 续签时保留旧条目并递增序号 |
| 有效期 `-ttl` | 全部 | 必录 | 24h | 最长 8760h |

**连接地址填什么**：本节点对外可达的 libp2p multiaddr，并以本节点 PeerID 结尾，例如 `/ip4/192.0.2.10/tcp/4001/p2p/12D3KooW...`，多个用逗号或换行分隔。订阅方会把这些地址并入 `staticPeers`，作为连接本节点的锚点。签发时会校验每一项都能解析为带 `/p2p/<PeerID>` 的地址，CLI **不会**自动补全，缺少就签发失败。

助手按 `network.announceAddrs` 预填：优先用运行中的配置，为空时用已保存的配置（待重启的场景）。每项自动拼上 `/p2p/<本节点PeerID>`，已带 `/p2p/` 的不重复拼接。配置文件中的 `announceAddrs` 本身不能含 PeerID。手工修改后不会被覆盖，可点“重新按公告地址填写”恢复。未配置 `announceAddrs` 时可以留空签发，但描述里不会带任何地址，异地节点必须另有 staticPeers、引导入口或中继才能发现本节点。

离线流程的三条手工注意事项：服务描述里公告的模型必须落在委托模型范围内，否则远程请求会被拒绝；续签吊销快照必须保留旧条目且序号递增，否则应用时会被拒绝回滚；使用离线发布者根私钥签发后回到本页导入签名文档，节点重启后新委托才生效。在线签发请使用上方“发布者签发管理”。

## 保存与生效

### 导出发布者元信息

进入“我的发布服务 → 导出服务描述”，查看发布者 ID、服务 ID、有效期、授权模型、服务节点、连接地址及中继地址，然后下载 `service.noobloft`。默认选择运行中服务；运行中尚未安装时选择已保存服务，待重启的配置会显示提示。导出接口要求独立管理凭证，并验证原文档签名与有效期；过期或签名损坏的文档不能导出。

下载文件保留原服务 ID 与完整签名，不重新签发、不携带节点密钥、管理 token 或模型后端密钥。消费者在“微网络订阅 → 添加订阅”中导入，并通过可信渠道核对发布者 ID；实际调用仍需单独导入消费凭证。

尚未安装服务委托时，抽屉会提示先通过发布者 CLI 离线签发，再安装服务委托和吊销快照。此功能是导出已有签名文档，不包含浏览器内创建根身份或签发消费凭证。

所有表单继续使用右侧抽屉：桌面宽度为屏幕的 82%（最大 1180px），平板为 94%，手机为全屏宽度。手机导航改为可横向滚动的顶部菜单。

### 配置变更

订阅、消费凭证、服务安装、配置修改均先保存，需手动重启节点生效。页面根据启动配置快照与保存配置比较显示状态。模型和连接列表来自运行时，不以保存配置伪装运行状态。

更新**当前运行服务使用的**吊销快照后，新请求立即受其约束，不中断已运行请求。若已安装待重启的新服务或新快照路径，更新的是保存配置引用的快照，需重启后才作用于当前进程。安装服务采用独立快照，不提前改变运行授权；失败会清理新建快照，历史快照不自动删除，以免误删仍被运行进程引用的文件。

修改配置使用版本校验，过期页面提交返回 409；刷新后重新编辑。CLI 发布者操作与 HTTP 写入共用配置锁 `.management.lock` 及业务校验。锁被占用时写操作返回 409；进程异常退出遗留的锁超过 2 分钟后由下一次写操作自动接管，无需手动删除。

网络 private/shared 迁移仍通过 CLI 准备；页面不支持切换网络模式，也不允许把网关改成新的非回环监听地址。删除订阅不删除共享引导/中继地址，避免破坏其他订阅或手工配置。

## 开发构建

需要 Go（版本见 go.mod）、Node.js 20.19+ 或 22.12+。

```sh
./scripts/build.sh
# Windows PowerShell: .\scripts\build.ps1
```

脚本使用 lockfile 安装前端依赖、构建 Vue 应用，再构建 Go 二进制。前端产物保存在
`internal/controlplane/webui/dist` 并由 `go:embed` 嵌入，但该生成目录不纳入版本控制。缺少前端产物时
直接运行 `go build` 会失败，避免生成没有管理控制台的二进制。Go 不会检查已有产物是否
与前端源码一致，因此修改前端后也应使用构建脚本，确保嵌入最新控制台。

开发时启动现有节点，再在 web 运行 `npm run dev`。Vite 将 `/manage` 代理到 127.0.0.1:8760，保持浏览器 Host 以符合管理接口同源检查。
