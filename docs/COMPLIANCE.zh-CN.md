# noobloft 责任规避与合规设计

> 本文是工程设计约束，不构成法律意见。正式发布前应由执业律师按目标市场复核。
> 核实日期：2026-09-25，来源均为官方一手文本。

## 当前工程边界

本文含历史设计要求，不是功能完成清单或合规结论。本次更新仅同步工程边界，未重新核验法律资料。
默认 private 使用 PSK；显式 shared 使用发布者委托和逐消费者授权，详见 [PUBLISHERS.zh-CN.md](PUBLISHERS.zh-CN.md)。
共享模式不等于匿名开放推理：模型入口验证凭证，共享中继使用 PeerID 白名单。
发布者发现键包含发布者作用域，DHT 记录不授予权限；签名仅证明声明归属，抽检仅检查可用性。
信誉是默认关闭的服务质量账本，不是侵权认定、滥用举报处理或法律合规证明。

## 0. 核心定位（一句话）

**做"纯通道"，不做"平台"。** 所有设计取舍都服务于一个目标：让节点在法律上尽量接近
"被动自动传输的网络管道"，而不是"组织、挑选、推广模型服务的中介平台"。

## 1. 法律依据（官方一手来源）

### 1.1 美国：DMCA §512(a) 纯通道安全港

17 U.S.C. §512(a) 保护传输、路由、连接及传输过程中的中间性短暂存储。
五项条件必须**同时**满足：

1. 传输由服务商以外的人发起
2. 通过自动技术过程完成，服务商不选择材料
3. 服务商不决定接收者（自动响应请求除外）
4. 中间副本不向预定接收者之外的人开放，保存时间不超过完成传输所需
5. 材料内容在传输中不被修改

另有全局门槛 §512(i)：必须制定、通知用户并**合理实施**重复侵权者政策，
并容纳标准技术措施。§512(m) 明确不要求主动监控。

来源：
- https://uscode.house.gov/view.xhtml?req=(title:17%20section:512%20edition:prelim)
- https://www.copyright.gov/policy/section512/section-512-full-report.pdf

**反面教材**：*BMG v. Cox Communications*（第四巡回法院）认定 Cox 屏蔽大量侵权通知、
对自身终止政策执行不力，因此未"合理实施"重复侵权者政策，丧失安全港。
**证明安全港资格的举证责任在服务商一方。**
来源：https://www.ca4.uscourts.gov/Opinions/161972.P.pdf

### 1.2 美国：Grokster 诱导侵权（P2P 软件的头号风险）

*MGM v. Grokster*, 545 U.S. 913 (2005)。规则：
> 分发设备或产品，并以促进其被用于侵权为目的，且该目的由明确表达或其他积极
> 促进行为显示出来的主体，应对第三方由此产生的侵权行为负责。

最高法院看重的三组证据，逐条对应本项目必须避免的行为：

| Grokster 的问题行为 | 本项目的约束 |
|---|---|
| 主动争取 Napster 的侵权用户 | 不在任何宣传中提及"绕过 API 限制""白嫖闭源模型""规避封号" |
| 未开发过滤工具（在已有诱导证据时强化恶意推断） | 默认内置滤规则与滥用报告通道 |
| 依赖高流量的广告变现模式 | 不做按转发流量抽成的商业模式 |

注意：Sony"实质性非侵权用途"不能对抗**故意诱导**；反之，仅提供中立连接、
知道网络上存在侵权，通常不构成诱导。
来源：https://www.govinfo.gov/content/pkg/USREPORTS-545/pdf/USREPORTS-545-913.pdf

### 1.3 中国：《生成式人工智能服务管理暂行办法》

七部门令第 15 号，2023-07-10 公布，2023-08-15 施行。

第十七条：提供**具有舆论属性或者社会动员能力**的生成式 AI 服务的，应开展安全评估，
并按《互联网信息服务算法推荐管理规定》履行算法备案及变更、注销手续。

关键边界：
- 仅内部研发或应用、**未向境内公众提供服务**的，不适用本办法
- 通过 API 提供服务的组织或个人，**属于"提供者"**
- 备案时限：提供服务起 10 个工作日内；变更 10 个工作日内；注销 20 个工作日内
- 已上线应用须在显著位置注明所用模型名称和备案号

**勿引用 2023-04 征求意见稿**（当时要求所有服务均需备案），正式文本已收窄。

来源：
- https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm
- https://www.cac.gov.cn/2022-01/04/c_1642894606364259.htm

### 1.4 欧盟：AI Act（Regulation (EU) 2024/1689）

角色三分，且**第五章只规制 GPAI 模型提供者，不存在"GPAI 模型部署者"义务类别**：

- GPAI 模型提供者：开发并以自己名义投放欧盟市场
- AI 系统提供者：把模型集成进自己品牌的产品对外提供
- 部署者（deployer）：在业务活动下使用 AI 系统，纯个人非职业用途除外

与本项目相关的要点：
- 仅使用第三方模型 API，一般**不会**自动成为 GPAI 模型提供者
- 微调不自动产生新提供者身份；指示性标准是修改算力超过原训练算力 1/3
- 第 50 条透明度义务：AI 直接交互须告知用户对方是 AI；合成内容须带机器可读标记
- 时间表：GPAI 提供者义务 2025-08-02 起适用，2026-08-02 起全面执法；
  第 50 条透明度义务 2026-08-02 起适用
- 罚则：违反第 16/26/50 条，最高 1500 万欧元或全球年营业额 3%，取较高者

来源：
- https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32024R1689
- https://digital-strategy.ec.europa.eu/en/faqs/guidelines-obligations-general-purpose-ai-providers

## 2. 架构层面的责任隔离设计

### 2.1 中继节点严格实现"纯通道"语义

对应 §512(a) 五要件，代码层面的硬约束：

```
中继设计要求（实际由 internal/network/node 集成 libp2p Circuit Relay v2）：
  ✅ 只转发，绝不解析 prompt / completion 内容
  ✅ 端到端加密：中继看不到明文（端点间 libp2p 安全通道；无额外应用层密钥协议）
  ✅ 不落盘：内存缓冲区上限 + 传输完成即释放，禁止写日志文件
  ✅ 不改写：字节级透传，不注入 system prompt、不做内容改写
  ✅ 不选择：路由决策由请求方 scheduler 做，中继只响应连接请求
```

反模式（会摧毁纯通道抗辩）：
- ❌ 中继侧缓存响应做"加速"→ 违反第 4 项短暂性
- ❌ 中继侧注入或改写 prompt → 违反第 5 项不修改
- ❌ 中继侧记录完整对话用于"调试" → 违反第 4 项且制造证据风险
- ❌ 中继侧做内容审核 → 自相矛盾：既主张被动通道又主动挑选材料

> 设计张力（需明确决策）：内容过滤与纯通道抗辩在**同一层**是冲突的。
> 解法是**分层**：过滤放在 provider 节点的入口（自己的模型自己负责），
> 中继层保持纯粹被动。§512(m) 支持中继无主动监控义务。

### 2.2 发现层不做"目录服务"

旧私网 DHT 使用模型名派生 CID；发布者模式使用版本化的发布者/模型发现键。
哈希不保证模型名保密，能力查询仍可能暴露模型元信息。
节点不运行中心化的"模型市场"网页，避免形成 §512(d) 意义上的信息定位工具，
也避免 Grokster 式"组织侵权内容"的外观。

### 2.3 能力声明签名与审计留痕

`/noobloft/1.0.0/capability` 返回的能力声明必须由 provider 私钥签名，包含：

```
peerID, modelName, modelLicense, licenseAttribution,
quantization, contextLength, jurisdiction, aupVersion, timestamp, signature
```

以下为历史设计目标，字段贯通与响应头行为须以代码和测试为准，不表示均已实现。
作用有三：
1. 把"声称跑什么模型"的责任明确归于 provider，而非中继或软件作者
2. `modelLicense` + `licenseAttribution` 字段让 Llama 类署名义务可机器校验；
   consumer 侧网关自动把 `Built with Meta Llama 3` 透出到响应头
3. 留痕仅保存签名与元数据，**不保存推理内容**，兼顾审计与纯通道

### 2.4 §512(i) 重复侵权者政策必须真正执行

以下是历史待实施要求；当前 reputation 仅记录服务质量，不实现这些法律处置流程：

- `internal/serving/reputation/`：滥用报告 → 计分 → 达阈值自动加入本地 denylist
- 政策文本 + 联系邮箱随软件分发，并在首次启动时展示
- 终止记录可导出，用于证明"合理实施"
- 阈值与终止动作**默认开启**，不提供一键关闭的全局开关

### 2.5 默认安全的开关取向

| 开关 | 默认值 | 理由 |
|---|---|---|
| 作为中继为陌生节点转发 | **关闭** | 默认不承担陌生流量，用户显式选择加入 |
| 对外暴露本机模型 | **关闭** | 避免用户无意间成为"提供者" |
| 本地网关监听地址 | `127.0.0.1` | 绝不默认 `0.0.0.0` |
| 本地网关鉴权 | **开启**（随机 token） | 未鉴权的 HTTP 网关等于开放代理 |
| 匿名中继/洋葱路由 | **不实现** | 强匿名设计会被视为规避意图的证据 |

> 最后一条是刻意的取舍：技术上可做多跳匿名，但那会直接喂给 Grokster 分析
> "积极促进行为"的推断。可追溯的单跳中继在法律上安全得多。

## 3. 分发端责任规避

### 3.1 软件本身

- 许可证选 **Apache-2.0**（含明示专利授权与贡献者免责），配 `NOTICE`
- README 首屏写明用途定位：**自有算力的私有组网与算力共享**，
  不写任何"访问受限模型""绕过限制"的字样
- 附 `DISCLAIMER.md`：AS IS、无担保、用户自负合规责任
- 仓库置 `ACCEPTABLE_USE.md`，直接引用并要求遵守所连接模型各自的 AUP
- 不提供任何预置的、指向第三方商业 API 的转发配置或密钥

### 3.2 运营端（若自建 bootstrap / 公共中继）

- bootstrap 节点只做 peer 发现，不做内容索引，保留最小连接日志满足取证要求
- 登记 DMCA 代理人：虽然 §512(a) 本身不要求，但一旦你还托管网站/文档/索引，
  那部分适用 §512(c)，需要独立评估
- 若面向中国境内公众提供服务，且服务具舆论属性或社会动员能力
  → 触发安全评估 + 算法备案 + 显著位置标注模型名与备案号
- 若面向欧盟：确认自己是 deployer 还是下游 AI system provider；
  第 50 条要求在交互界面告知用户"对方是 AI"

### 3.3 商业模式的红线

不要做按转发流量抽成。Grokster 中"使用量越大收入越高"被用来推断
"意图从侵权规模中获利"。可行替代：
- 纯 P2P 互惠配额（tit-for-tat 双向带宽额度，不涉货币）
- 对企业私有部署收订阅费（与流量规模脱钩）

## 5. 待确认的开放问题

1. 运营范围：仅自用/内部组网，还是面向公众？这决定中国侧是否触发第十七条，
   以及欧盟侧角色定性——是本文档所有结论的最大分叉点。
2. 是否运营公共 bootstrap / 中继：运营即从"软件作者"变为"服务提供者"，
   责任量级不同。
3. 是否支持转发指向闭源商业 API：这会引入各家 ToS 的违约风险
   （通常禁止转售与共享凭据），与 §512 和 AI Act 是彼此独立的风险层。
   建议第一版**仅支持自托管开源模型**。
